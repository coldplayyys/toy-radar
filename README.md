# 潮玩雷达 · 数据同步与固定链接说明

## 一、数据是怎么“同步”进软件的

整个产品是纯静态前端，数据来自 `toy-radar-data.js`。同步的本质是**每周把新数据重新生成一遍**：

```
潮玩雷达数据/<日期文件夹>/潮玩品类数据7.26-8.1.md   ← 每周放入新 md（文件名带上周区间，可放在日期子文件夹）
        │  python generate_toy_radar_data.py
        ▼
toy-radar-data.js                       ← 自动重新生成，周快照自动累积
        │
        ▼
index.html / toy-radar-app.js           ← 页面直接读取展示
```

生成器会递归扫描 `潮玩雷达数据/` 下所有 `潮玩品类数据*.md`（含日期子文件夹），按周排序追加到 `weeklySnapshots`，
所以**趋势页的折线每周会自动多一个真实数据点**，不需要改任何前端代码。

### 每周要做的三件事

1. 把新一周的表格整理成 md，文件名写成 `潮玩品类数据7.26-8.1.md` 这种格式（周区间写在文件名里），放进 `潮玩雷达数据/` 下任意位置（建议按日期建子文件夹）；
2. 运行 `python generate_toy_radar_data.py`；
3. 部署（见下文固定链接方案）。

### 同名商品怎么合并

生成器会在**整周范围**内把同名商品合并成一条（不同店铺、不同渠道、不同榜单都算）：

- 销量求和，例如 20万+ 与 10万+ 合并显示 30万+；
- 价格给区间，例如 69–89；
- 店铺保留明细，榜单显示「主店铺 等 N 家」，点进详情能看到每家店的销量与价格；
- 商品名归一化只用于判断“是不是同一款”（忽略空格、大小写、×/x、全半角括号），展示名保持不变；
- 同一款同时出现在多个品类榜单时，归入主记录所在品类。

想再省一步，可以做成全自动：

- **本机自动**：用 Windows「任务计划程序」每周定时跑一次第 2 步（`python generate_toy_radar_data.py`），前提是第 1 步的 md 已经放进文件夹；
- **云端自动**：仓库里已带 `.github/workflows/deploy.yml`，每周日自动重新生成并发布，第 2、3 步都不用手动做；
- **Codex 自动化**：也可以让 Codex 每周定时提醒你拖入新数据并执行生成。

## 二、把榜单截图变成数据（OCR 流水线，全本地）

每周从公众号（如「IP文创潮」）拿到的通常是一堆榜单截图。`ocr_toy_data.py` 把它们识别成
`generate_toy_radar_data.py` 能直接解析的六列表格，**不需要任何 API Key**（本地 RapidOCR，
依赖：`pip install rapidocr_onnxruntime`）。

```powershell
# 1. 先看识别效果，不写文件；--dump 顺便导出识别原文（校对用，也是下次调参的缓存）
python ocr_toy_data.py "潮玩雷达数据/8.15数据" --dump "潮玩雷达数据/8.15数据/ocr原文"

# 2. 生成周数据 md（文件名必须带周区间，生成器才会按周累积）
python ocr_toy_data.py "潮玩雷达数据/8.15数据" --write --week "8.9-8.15"

# 3. 重新生成前端数据并部署
python generate_toy_radar_data.py
```

会产出三样东西：

- `潮玩品类数据<周区间>.md`：六列表格，品类 / 商品名 / 已售 / 单价 / 店铺 / 统计日期；
- `潮玩品类数据<周区间>-待核对.md`：**需要人工扫一眼的行**（数字没认全、置信度低、或水印粘进数字）；
- `潮玩雷达数据/<周>/ocr原文/`：每张截图的原始识别文本（含坐标），排查问题时用。

识别噪声在 `ocr_corrections.json` 里维护：左边写错字、右边写对的；右边留空字符串就是删掉
（公众号水印常用这招）。发现的错字补一次，后面每周都省事。

对着三周人工整理的旧 md 实测：**商品名几乎全部命中，可用商品行召回约 86%**，
剩下每期 17 行左右进待核对清单。也就是说它替代的是「手打表格」，不是「最后一道校对」。

想随时量一下准确率：

```powershell
python ocr_toy_data.py "潮玩雷达数据/8.15数据" --compare "潮玩雷达数据/8.15数据/潮玩品类数据8.9-8.15.md"
```

## 三、固定链接怎么来

按“稳定程度”分三档，从零成本到正式发布：

### 档位 1：本机固定链接（最快，仅供自己看）

双击 `启动仪表盘.bat`，浏览器会自动打开 **http://localhost:8000/**。
端口固定，所以这个地址在你电脑上是“固定”的，但只有你本机能访问。

### 档位 2：局域网链接（演示当天可用）

同一 Wi-Fi 下先跑 `启动仪表盘.bat`，再用以下命令查本机 IP：

```powershell
ipconfig
```

把 `IPv4 地址`（如 `192.168.1.8`）告诉评委，他们访问 `http://192.168.1.8:8000/` 即可。
若打不开，多半是 Windows 防火墙拦截了 8000 端口，放行 Python 即可。

临时公网链接（现场演示急救）：可以用 [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)
或 ngrok 给本机 8000 端口生成一个临时公网地址，演示当天够用，但地址不固定。

### 档位 3：正式固定链接（推荐，免费且长期有效）

用 GitHub Pages 发布，链接形如 `https://<你的用户名>.github.io/<仓库名>/`，永久固定、评委随时可打开。

一次性配置步骤：

1. 把这个文件夹变成 git 仓库并推到 GitHub：

   ```powershell
   git init
   git add .
   git commit -m "潮玩雷达 v1"
   git branch -M main
   git remote add origin https://github.com/<用户名>/<仓库名>.git
   git push -u origin main
   ```

2. 打开仓库 **Settings → Pages**，在 “Build and deployment” 里把 Source 选成 **GitHub Actions**；
3. 工作流 `.github/workflows/deploy.yml` 已经就位：每次 `push` 或每周日定时都会自动重新生成数据并发布；
4. 等第一次跑完，访问 `https://<用户名>.github.io/<仓库名>/` 即可。

之后每周只需要把新 md 提交推送到 main 分支（或让云端定时任务处理），链接不变、数据自动更新。

## 四、知识库（RAG）：已从主导航收起，代码保留

当前站点只保留「搜索 / 销量 / 趋势 / 种草」四个入口，知识库标签与脚本已从 `index.html` 移除；
`toy-radar-kb.js`、`kb_server.py` 与 `vendor/` 仍完整保留，需要时把标签、视图和脚本加回即可恢复。
以下内容用于恢复后的使用说明。

页面第四个标签「知识库」是一条完整的本地 RAG 闭环：

```
上传资料 → 解析（PDF / Word / TXT / Markdown / HTML）→ 切块（保留页码、块间重叠）
        → 建索引（关键词 BM25 + 可选向量）→ 提问检索 → 大模型只依据检索到的原文作答
        → 每条结论标注 [1][2] → 点击引用跳回原文那一页并高亮
```

**怎么用**

1. 双击 `启动仪表盘.bat`（它现在会跑 `kb_server.py`，既是网站服务器，也是大模型代理）；
2. 打开「知识库」标签，把 PDF / Word / Markdown 拖进去，或者点「导入站内榜单数据」
   用现成的三周数据先试一次；
3. 在右侧提问，比如「这三周盲盒品类的销量结构发生了什么变化？」。

**两种模式**

- **不填 Key**：直接是「检索 + 原文片段」模式，按相关度返回 6 段原文，点「查看原文」读上下文。
  演示、内部查资料都够用，也不需要任何费用。
- **填 Key**：在「模型设置」里选服务商（DeepSeek / 硅基流动 / 智谱 / Kimi / OpenAI / 自定义）、
  填 Key 和模型名，之后就是流式作答，每条结论带 `[编号]`，点编号直接跳到原文那一页并高亮。

**模型怎么挑**（以 DeepSeek 为例，实测同一份资料同一个问题）

| 模型 | 首段正文出现 | 适用 |
|---|---|---|
| `deepseek-flash` | 约 8 秒 | 日常问答，够快，引用照样标 |
| `deepseek-v4-pro` | 约 22 秒起（波动到 1 分钟） | 需要多步推演、交叉比对时更稳 |

这两个都是推理型模型：先输出一大段思考，正文才出来。页面会显示「模型仍在推理（已思考 N 字）…已用 N 秒」，
不是卡住了。**DeepSeek 没有向量接口**，想开向量检索得换一家能给 embedding 的服务商
（如硅基流动的 `BAAI/bge-m3`、智谱的 `embedding-3`）。

**几个设计取舍**

- **完全跑在浏览器里**：解析、切块、索引都在本机完成，文档不出门；文档与切片存在 IndexedDB，
  刷新不丢，换浏览器才需要重新导入。
- **关键词打底、向量可选**：中文 BM25 用单字 + 二元组切词，不依赖任何分词服务；
  想开向量检索就填一个向量模型（如 `BAAI/bge-m3`），会和关键词分数混合排序。
  没有向量模型时，检索照样能用。
- **本地代理绕开跨域**：很多国内模型接口不给浏览器发 CORS 头，直连会被拦。
  `kb_server.py` 提供一个 `/api/llm/*` 代理（只允许转发到 https 公网地址），
  Key 只在本机内存里过一手，不写进任何文件。部署到 GitHub Pages 后没有这个代理，
  页面会自动退回直连模式（能不能用取决于服务商是否允许跨域）。
- **引用可回溯**：答案里的 `[n]` 不是装饰，点它就会打开原文阅读器，跳到对应页并高亮那句话；
  找不到对应片段时不会假装有引用。

**依赖与许可**：解析用的 `vendor/pdf.min.mjs` + `pdf.worker.min.mjs`（pdf.js，Apache-2.0）和
`vendor/mammoth.browser.min.js`（mammoth.js，BSD-2-Clause）都已放进仓库，演示时不怕 CDN 打不开。

**测试**：`node tests/kb.test.js` 覆盖分词、切块、BM25、混合排序、引用解析、原文定位、
SSE 流式分包这些纯逻辑（10 项）。其中 SSE 那条专门验证「一行 JSON 被网络切成两半」的情况。

## 五、公众号周更：文章 → 图片 → 数据（新增）

公众号「IP文创潮」每周把数据以**图片表格**的形式发在文章里。现在可以一条命令把文章接进潮玩雷达：

```powershell
# 1. 抓文章图片（只读，不改公众号内容）
python fetch_wechat_article.py "https://mp.weixin.qq.com/s/xxxx" --out ".scratch/wechat/本周"

# 2. 一条命令跑完：OCR → 质量校验 →（可选）写入数据目录
python sync_wechat.py "https://mp.weixin.qq.com/s/xxxx" --week "9.7-9.13" --date "2026.9.12" --out ".scratch/wechat/本周"

# 3. 人工核对「待核对清单」后发布
python sync_wechat.py --out ".scratch/wechat/本周" --week "9.7-9.13" --date "2026.9.12" --reuse --publish
```

**它是怎么工作的**

1. 抓取文章页 → 从正文 `#js_content` 里按顺序取 `data-src` 真实图片地址（带 Referer，绕开防盗链）；
2. 保存图片 + `manifest.json`（标题、公众号、发布时间、尺寸、哈希），以后可回查数据来源；
3. 交给 `ocr_toy_data.py`：还原表格、拆粘连数字、纠错水印，非表格图片自动跳过；
4. 质量门禁：商品行数、品类覆盖、统计日期、待核对比例，任何一项不过就拒绝发布；
5. `--publish` 才写入 `潮玩雷达数据/<日期>/` 并重新生成前端数据，默认只产草稿。

**实测（2026-09-13 发布的「文创潮周汇245期」）**：正文 25 张图，下载 21 张（2 张为占位图）；OCR 识别出 10 张数据表（8 张商品榜 + 2 张店铺榜），得到 78 行可用商品、覆盖 4 个品类，14 行进入待核对清单（18%），质量门禁全部通过。

**注意事项**

- 微信偶尔返回"环境异常"页。此时用浏览器打开文章、另存为 HTML，然后改用 `--html 文件路径`；
- 表名优先于商品词频决定品类：「手办热销榜」里混着盲盒商品时，仍归入可动手办（已修）；
- 同一周重复运行会拒绝写入，确认覆盖要加 `--force`，避免快照重复；
- 抓取用的是公开页面，请低频使用；每周一次即可，不要做轮询。

**自动化的建议位置**：放在你自己的电脑上（Windows 任务计划程序），周一早上执行 `sync_wechat.py`，跑完 `git push`；GitHub Actions 继续只负责部署。机房 IP 访问公众号更容易触发风控。

## 六、常见问题

- **趋势图为什么只有本周一个点？** 因为目前只有一期真实快照。把第二周 md 放进去重新生成后，
  趋势线会真实长出来；页面上“演示模式”只是展示形态的模拟数据，已明确标注。
- **数据来自第三方榜单（蝉妈妈/抖查查等）能全自动吗？** 可以，但需要额外一步：写一个抓取脚本把榜单
  转成 md 放进数据目录（通常需要账号/API 凭证）。当前方案默认你手工粘贴整理成 md，之后的生成、累积、发布都是自动的。
- **换了电脑怎么办？** 用档位 3 把仓库推到 GitHub，任何电脑 clone 下来跑一次生成器即可。
- **知识库里问问题时提示「生成失败：HTTP 401」？** 说明 Key 不对或额度用尽——报错原文来自模型服务商，
  直接看提示里的信息即可。Key 过期就去服务商后台换一个。
- **提示「Failed to fetch」或跨域被拦？** 直连模式下浏览器被服务商挡了。用 `启动仪表盘.bat`
  打开网站（走本地代理），或在「模型设置」里勾上「优先走本地代理」。
- **PDF 上传后提示没解析出文字？** 多半是扫描件（图片版 PDF），需要先 OCR。
  本仓库的 `ocr_toy_data.py` 就是干这个的，可以把识别结果再粘成 Markdown 传进知识库。
